**Status:** Complete

## 3. Endpoints

| Method | Address | Purpose |
|---|---|---|
| GET | `/health` | Confirms the server is running. Returns `{"status": "Jarvis is online"}` |
| POST | `/chat` | Send `{"message": "..."}`, receive `{"reply": "..."}` |
| GET | `/history` | Shows the last 50 saved messages |
| GET | `/docs` | Automatic interactive guide generated by FastAPI |

Run the server from `C:\Jarvis\backend` with the environment active:
```
uvicorn main:app --reload
```
Address: `http://127.0.0.1:8000` (reachable from this laptop only).

## 4. Code reference

### database.py
All database logic lives here.

- `DB_PATH`: the file `jarvis.db`, saved next to the code.
- `init_db()`: creates the `messages` table if it does not exist (columns: `id`, `role`, `content`, `created_at`).
- `add_message(role, content)`: saves one message.
- `get_recent_messages(limit=20)`: returns the most recent messages in chronological order.

Key rules applied:
- Queries use `?` placeholders, never text glued into SQL, to prevent SQL injection.
- Only the last 20 messages are sent to the model, because the context window is 4096 tokens and the full history would eventually overflow it.

### main.py
- Calls `init_db()` at startup.
- `POST /chat` flow: save the user message, load the last 20 messages, prepend the system prompt, call the model, save the reply, return it.
- The system prompt is added fresh on every call and is **not** stored in the database, so it can be edited later without touching old data.
- Endpoint functions are plain `def`, not `async def`. The model call blocks while it thinks, and FastAPI runs plain functions in a worker thread so the server stays responsive.

## 7. Known limitations

- **Single conversation.** All messages share one history. No separate sessions or users yet.
- **Fixed 20-message window.** Older messages are stored but not sent to the model. Long-term recall (facts, notes, summaries) is planned for a later topic.
- **Local only.** The server listens on `127.0.0.1`, so nothing else on the network can reach it. This is intentional for now.
- **Manual start.** The server must be started by hand. Auto-start at login is planned with the sphere topic.
- **Edits from `--reload`.** Saving a file restarts the server. With database memory this is now harmless.
